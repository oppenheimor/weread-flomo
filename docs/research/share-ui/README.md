# 分享功能 UI 调研

## 范围与证据

通过 Pinterest 登录态浏览器实际搜索、查看图片与 Pin 详情。搜索词：`share link modal ui`、`bookshelf reading app ui`、`reading highlights notes app ui`、`404 page book illustration`。

以下是视觉参考，不是可用性测试结论；未运行这些设计的真实产品交互。截图仅作内部研究，不作为产品资产。未保存 Pin、关注账号或发布任何内容。

## 推荐方案（设计建议，尚未实现）

### 分享人

书架页放“分享书架”，书内放“分享本书”，两个入口共用面板结构。

未开启：
- 分享书架 / 分享《书名》
- 范围说明：开启后，任何拿到链接的人都可以查看全部书籍及划线和想法 / 本书的全部划线和想法。
- 主按钮：开启分享并复制链接。

已开启：
- 状态：分享已开启。
- 链接 + 复制链接，成功后显示“已复制”。复制失败保留可选中的链接，并提示手动复制。
- 次要操作：预览分享页。
- 低强调危险操作：关闭分享。
- 关闭确认：关闭后，当前链接永久失效。再次开启会生成新链接。

打开面板本身不创建分享。开启请求成功、复制失败是不同结果，不能把已开启误报为失败。重复复制或重新打开面板不更换链接。

### 朋友

书架 → 点选书籍 → 章节切换 → 阅读划线与想法。

- 不需要登录或配置，不显示 API key、AI、同步状态、勾选、编辑控件。
- 从书架进入的书内页可返回该分享书架；独立单书链接没有书架入口。
- 手机优先照顾正文阅读宽度，章节入口保留，避免常驻大侧栏。
- 加载显示骨架；无划线/想法显示明确空状态；接口失败显示重试；链接无效才走插画 404。
- 内容不按 flomo 状态过滤，已同步的原始笔记同样展示。

## 已确认产品边界

全部书与原始划线/想法公开，不逐条隐藏；数据实时获取，不做快照；后端使用分享人的凭据；匿名只读；书架和单书分享分别开关；关闭后旧链接永久失效；重新开启新链接；不展示 AI 内容。
