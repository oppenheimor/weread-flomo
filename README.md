# 微信读书 → flomo

支持开放注册的多账号 Web 应用。前端 **Vite + TypeScript + React**，后端 **Java 21 + Spring Boot 3.5**，数据库 **PostgreSQL**。

登录后选书 → 拉取 → 预览勾选 → 确认发送。每条划线一条 memo，关联想法附后；独立想法/书评单独发送。不保留微信读书原始 JSON。

## 数据与安全

- PostgreSQL 保存每个账号的 BCrypt 密码摘要、登录会话和同步账本，按账号隔离；浏览器不保存这些数据。
- HttpOnly / SameSite=Strict Cookie；HTTPS 部署必须开启 Secure Cookie。
- Spring Security CSRF 校验、固定 Origin 校验。开放注册：账号 3–64 位字母、数字、点、下划线或横线，密码非空、最多 72 UTF-8 字节；注册后登录并配置自己的凭证，无邮箱验证或密码找回。
- 登录限速：每账号每五分钟十次、每连接 IP 每五分钟一百次；注册每连接 IP 每五分钟五次。忽略客户端转发 IP 头，反向代理部署时同一代理下用户会共享 IP 配额，公网入口应另设限速。
- 登录后在“账号设置”填写、更新或删除微信读书/flomo 凭证，按用户使用 AES-256-GCM 加密存入 PostgreSQL。随机 IV，认证数据绑定用户 ID 和平台，不能跨用户/平台替换密文。
- 环境变量只保留服务端 `CREDENTIAL_ENCRYPTION_KEY` 主密钥。状态查询和保存响应不返回完整凭证；默认显示固定掩码，仅点击眼睛后通过已登录、CSRF 保护的 POST 接口读取当前账号明文（no-store）。隐藏、切换窗口或关闭弹窗后清除查看状态，不写入日志或浏览器存储。未填写的字段不修改；删除需二次确认。
- 修改凭证会清除该用户的书籍缓存和预览，不清空同步记录。凭证修改与拉取/发送互斥，防止批次中途换账号或目标。
- 预览只在服务端内存保留 30 分钟，重启后重新拉取；账本长期保存在 PostgreSQL。
- 先落账再发送；成功回执为 `code=0` + 顶层 `memo.slug`。失败/超时停止批次，结果不确定不自动重试。
- 单实例 PostgreSQL advisory lock；禁止双活；启动恢复遗留 sending 为 uncertain。
- flomo 每天 API 最多 100 条，包含其他工具的写入。每批最多 100 条。

## 本地开发

需要 Java 21、Node.js 24+ 和可用的 PostgreSQL。Maven Wrapper 已提供。

1. 安装前端依赖：`npm ci`。
2. 建立独立数据库和非超级用户账号。
3. 在项目 `.env` 中补齐 `.env.example` 所列的数据库、账号配置，运行 `node scripts/setup-encryption-key.ts` 生成加密主密钥（已有时不会覆盖）。本机已生成主密钥，不需要重复生成。
4. `ADMIN_USERNAME` 为 3–64 位英文、数字、点、下划线或横线；`ADMIN_PASSWORD` 至少 12 字符，最多 72 UTF-8 字节。只在空数据库第一次启动时创建账号，已有账号不会随环境变量变化重置密码。
5. `npm run backend:dev` 启动 Java，默认 127.0.0.1:18081。
6. `npm run dev` 启动前端，默认 127.0.0.1:5173，`/api` 代理到 Java。

登录需要固定 Origin：若 5173 被占用，设置 `FRONTEND_PORT=5175`，同时设置 `APP_PUBLIC_ORIGIN=http://127.0.0.1:5175`，再重启前后端。现在不再自动换端口，避免登录校验与页面地址不一致。

旧 Node 后端已移除。`.env` 中旧的 `WEREAD_API_KEY` / `FLOMO_API_URL` **已不再读取，不作为任何用户的默认凭证**。重启 Java 后登录，在“账号设置”粘贴原值并保存；不会自动把旧全局密钥归到某个账号。保存成功后可从 `.env` 删除这两个旧字段。

加密主密钥需要与数据库分开安全备份；丢失后无法恢复原凭证，只能重新配置。不要通过修改主密钥来“重置配置”，当前不支持自动密钥轮换。

## 书籍信息

登录后首页即书架：自动加载有笔记的书，封面角标显示未同步条数（概览划线数 + 想法数 − 账本已记录条数；打开过的书以实际预览为准）。点书进入独立章节页，自动拉取，待发送默认不选；跨章累计选择，底部按钮统一发送，每条笔记独立写入 flomo。凭证在右上角“设置”弹窗中管理。微信读书 Key 必配，缺少时自动弹出设置；首次仅填它即可保存并加载书架。flomo 凭证选配，不影响读取书籍和预览笔记，仅发送到 flomo 时需要配置。

只允许已核实的两个官方 CDN 域名作为封面，不代理任意 URL，图片请求不发送页面 Referer；缺图使用书名占位。readingProgress 按实际数据（0–100）显示为“读到 N%”，超出范围时原样显示；markedStatus=1 显示已读完。

发送结果不确定的笔记在“需核对”标签中处理：到 flomo 核对后选择“已有”（标记已同步）或“没有”（移除该条账本记录，回到待发送，仍需手动再发）。两者都需二次确认，系统不会自动重发。

## 旧本地记录迁移

多账号数据库导入时必须加 `--app.import-user=目标账号`，不会自动选择其他用户。升级启动会自动执行 V3 迁移，解除旧的单账号限制，保留原账号及数据。

旧 `data/sync.sqlite` 已保留，不会自动导入或删除。开始在新数据库同步前应先迁移，以免重复写入已有 flomo 笔记。

```bash
# 先停止旧服务；导出文件含私人笔记，权限 0600，不要提交 Git。
npm run export:ledger -- data/ledger-export.json
```

安全传输到服务器后，在首次启动 Java 时添加：

```text
--app.import-ledger=/受保护路径/ledger-export.json
```

只导入 sent/uncertain，不覆盖已有记录；迁移在事务中进行，可重复执行。导入后核对数量，删除迁移文件并移除参数。此工具是一次性 Node/TS 离线脚本，不是后端服务。
